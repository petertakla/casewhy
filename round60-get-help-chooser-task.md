# New task for Claude Code — round 60: a "which one do I need?" chooser for Get Help

**Status: authorized now, Sep 10 — revised twice, same day, before build started.** Peter's original ask, verbatim: "we also need a way to walk-thru a user on how to choose the best help needed, maybe q/a to narrow down available options or a static list of each entity and when to use." Follow-up 1: "is there an opportunity to use AI questions to a) help user b) id the need for AI questions" — yes to both. That revision then surfaced a real gap: `/ask` (CaseWhy's existing AI chat) requires sign-in and a tracked case, so routing a cold Get Help visitor there isn't zero-friction — asked Peter directly whether to ship the honest sign-up-gated version alone or build the zero-friction version too. Follow-up 2, verbatim: "I think we should have both." This revision adds that: a new, genuinely zero-friction anonymous general-question AI surface (Phase B below), alongside the existing chooser and the honest-copy sign-up path to `/ask` (Phase A, unchanged from the prior revision). Build Phase A first — it's fully shippable on its own — then Phase B; report progress on each separately if they end up spanning more than one sitting.

## The real problem

`/get-help` (`src/app/get-help/page.tsx`) currently lists every live category with a one-line *what it is* description (`LIVE_CATEGORIES`), but nothing tells a visitor *which one applies to them* — or whether they need an external human resource at all. A real share of visitors landing on this page don't need a lawyer or a nonprofit; they need a plain-language answer to something like "what does this status mean" or "what's an RFE" — which is exactly what CaseWhy's own AI case chat already does, for free, with no cap (round 52's "unlimited AI questions" differentiator). Today `/get-help` doesn't say that anywhere; it only ever points outward.

Checked directly against the live file before writing this: today there are 5 live categories (Attorneys, Accredited representatives, Legal aid & nonprofit organizations, DSO/university international student offices, Community & cultural organizations) plus 1 coming-soon placeholder (Employers). Round 58 (pro bono immigration-court representation) is authorized but not yet built as of this writing — build round 60 so it doesn't hardcode "5 live categories" anywhere and slots in cleanly whichever of round 58's category is live or not live by the time this ships. If round 58 has already shipped by the time you start this, include it normally.

## Phase A — the chooser, static list, and honest AI routing to `/ask`

**1. Centralize the entity-type data first.** Right now `LIVE_CATEGORIES`/`COMING_SOON_CATEGORIES` live only in `get-help/page.tsx`. Pull them into a shared module (e.g. `src/lib/get-help/entity-types.ts`) with one entry per entity type: `href` (nullable while coming-soon), `label`, `description` (the existing "what it is" copy), `whenToUse` (new — a short, concrete "use this when..." sentence, not a restatement of the description), and `status` (`"live" | "coming-soon"`). Both the hub page's static list and the new chooser read from this one module — no duplicated category data to drift out of sync, same lesson round 58's own task doc already called out about grepping for hardcoded entity lists instead of trusting memory. Draft `whenToUse` copy to refine, grounded in what's actually confirmed about each type from the round docs that built them:

- **Attorneys** — "You want a licensed professional who can formally represent you, sign filings on your behalf, or appear in immigration court for you."
- **Accredited representatives** — "You want professional legal help but a private attorney's fees are out of reach, or you'd rather work with a nonprofit."
- **Legal aid & nonprofit organizations** — "You need general guidance or a consultation and have limited income."
- **DSO / university international student offices** — "You're an F-1/M-1 international student with a status or SEVIS question tied to your school."
- **Community & cultural organizations** — "You want local, culturally or linguistically matched support — not necessarily legal help."
- **Pro bono immigration-court representation** (once round 58 is live) — "You're in immigration court / removal proceedings right now and need representation there, at no cost."
- **Employers** (still coming soon) — leave `whenToUse` null/omitted until this ships.

Refine this wording as needed, but keep it a concrete trigger a visitor can self-match against — not marketing copy.

**2. Static list, upgraded.** On `/get-help` itself, show `whenToUse` alongside (or instead of) the current one-line description for each live category — this alone answers Peter's "static list of each entity and when to use" ask, works with JS disabled, and costs nothing to maintain once the shared data module exists.

**3. A short guided chooser — fixed tree, this is the reliable default path.** A client-side, multiple-choice branching flow (no free text, no DB table — this is fixed logic over the same static data) that asks 2-3 short questions and ends on a recommendation of one or two real entity types, each linking straight to that category's page. This stays deterministic and JS-only-but-LLM-free, so it works even if the AI-assisted path below is ever unavailable or rate-limited. Starting draft of the tree (refine as needed, but keep every branch ending on a real outcome and keep an escape hatch at every step):

- Q1: "What's going on right now?" — *I don't understand something about my case, a status, or a term I saw* → recommend CaseWhy's AI chat directly, not a human directory (see "AI-assisted routing" below — this is the new branch). · *I'm in immigration court / removal (deportation) proceedings* → recommend pro bono immigration-court representation (round 58, once live) and Attorneys. · *I have a pending case/application and want legal advice* → Q2. · *I need general or community support, not necessarily legal* → Q3. · *I'm an F-1/M-1 international student with a school question* → DSO. · *I'm an employer* → the coming-soon placeholder's message, not a dead end.
- Q2: "Can you pay for a private attorney?" — *Yes* → Attorneys. · *No / not sure* → Accredited representatives + Legal aid & nonprofit organizations (both, not a forced single pick — they legitimately overlap).
- Q3: "Legal guidance on a low income, or general community support (translation, cultural navigation, referrals)?" — *Legal guidance* → Legal aid & nonprofit organizations. · *Community support* → Community & cultural organizations.

End state: show the recommended card(s) using the same card styling already on `/get-help`, plus a visible "not sure, or want to see everything?" link straight to the static list below it — never a dead end with only one recommendation and no way out.

**4. AI-assisted routing — the new piece, answering Peter's follow-up directly.** Two distinct things, don't conflate them:

- **(a) AI helps the user narrow down.** Alongside the fixed-question tree, offer an optional "or describe your situation in your own words" box. Submitting it calls the *existing* chat/guardrail backend (whatever already powers the case-status AI chat — reuse it, don't stand up a second unvetted LLM path) with a system prompt constrained to return **only** one of: a specific real entity-type from the shared data module, "CaseWhy's AI chat can likely answer this directly" (see (b)), or "not sure — here's the full list" as a fallback. The model must never be allowed to free-write advice-shaped prose about someone's actual case in this flow — its only job is picking a lane, using the same allow-listed set of outcomes the fixed tree already uses. Render whatever it returns through the same recommendation-card UI as the fixed tree, so a visitor can't tell which path they took.
- **(b) The chooser identifies when AI questions ARE the need.** Give "ask CaseWhy's AI" a real, first-class outcome in both the fixed tree (Q1's new first option, above) and the AI-assisted path — not just another footnote. This is a real product opportunity Peter's follow-up surfaced: today `/get-help` only ever points outward to external people; it should also point inward to the AI chat CaseWhy already has. **In Phase A, this outcome points to `/ask`** — checked directly, and it changes the CTA copy: `/ask` (`src/app/ask/page.tsx`) requires sign-in *and* a tracked case with a real receipt number before any question can be asked — it's case-grounded (`statusText`/`formType` passed into `CaseChat`), not a generic Q&A box. So this outcome is not a one-click destination the way the other categories are; be honest about that in the recommendation card's copy — something like "Create a free account and track your case, then ask us anything about it — no cost, no cap on the free plan today" rather than anything implying an instant answer with no further steps. Don't overpromise here; the whole feature's credibility rides on every recommended outcome actually delivering what its copy says. **Once Phase B ships (below), re-point this outcome to the new zero-friction surface instead**, with `/ask` demoted to the natural upsell surfaced at the end of that conversation ("want this answered specific to your case? sign in and track it").

**The one hard guardrail on both (a) and (b): never let "ask our AI" be the recommended outcome for a situation that plainly needs a licensed human** — the court/removal-proceedings branch, or anything else where the fixed tree already routes to Attorneys/pro bono representation. The AI-assisted free-text path must carry the same hard-rule discipline the main case-status chat already has for its own mandatory-professional-referral scenarios (the guardrail system from earlier rounds) — reuse that pattern here rather than inventing a new one, and if the existing guardrail rules don't already cover "this describes removal proceedings / a filing deadline / needing representation," extend them rather than leaving this flow unguarded. This is the actual safety-critical part of the whole feature — get it right before anything else, and it applies with equal force to Phase B below.

## Phase B — a zero-friction anonymous "ask CaseWhy" mode

Peter's call, verbatim, when asked whether to ship Phase A's honest-but-gated AI routing alone or build the no-signup version too: **"I think we should have both."** This is the genuinely differentiating piece — every other Get Help category requires zero commitment to browse (click, see a list); today the AI option is the only one that demands an account first. Fixing that is what makes "ask AI" a real first-class option in the chooser rather than a second-class one.

**What it is.** A new, publicly reachable question-answering surface — no sign-in, no tracked case, no receipt number — grounded in CaseWhy's policy knowledge base (the same KB the case-grounded chat already uses) rather than in any specific person's case, since there's no case to ground it in for an anonymous visitor. Scope it to general process/policy questions ("what does RFE mean," "what's the visa bulletin," "how does adjustment of status work," "what happens after biometrics") — not "what does MY status mean," which genuinely requires a tracked case. If someone asks something that needs their specific case data, the honest answer is to say so and offer the sign-in + track-a-case path — that's the natural, non-pushy upsell moment into the full product, not a dead end.

**The real new risk: abuse/cost exposure, because there's no account to rate-limit against.** This is the one genuinely new problem Phase A didn't have. Build real, enforced rate limiting before this goes anywhere near production traffic — IP-based and/or a first-party cookie/fingerprint, a conservative starting cap (in the ballpark of the free tier's per-case cap, e.g. a handful of questions per IP per day — pick and justify a real number, don't ship an unenforced or aspirational limit), and a clear, honest in-UI message when the cap is hit (not a silent failure). Flag in your completion report what cap you chose and why, and whether you added any lightweight abuse signal (obvious bot/scraper traffic patterns) beyond the raw rate limit — this is a real, open cost-exposure question and Peter should see what you actually built and be able to tune the number, not just be told it's "handled."

**Guardrails carry over in full, and matter more here.** This surface is fully anonymous and more exposed to someone trying to extract real legal advice with no accountability trail — reuse the exact same guardrail/hard-rule system as the case-grounded chat and Phase A's AI-assisted routing (never weaken it for this surface), and the same hard rule applies without exception: never let this recommend itself in place of a licensed human for court/removal-proceedings/representation-need questions — redirect those to Attorneys/pro bono representation instead of answering them, same as everywhere else in this feature.

**Placement.** Wire it in as the default destination for the chooser's "ask CaseWhy's AI" outcome (both the fixed tree's Q1 branch and the AI-assisted free-text path) once built, and give it its own reachable surface too (a route, or embedded directly in the Get Help chooser without navigating away — pick whichever fits the existing `/ask` page's patterns better; just don't collide with `/ask`'s route or component). Don't persist anonymous conversation content tied to identifying info beyond what genuinely supports the rate limit (an IP/cookie + timestamp, not indefinitely retained full transcripts) — same "we don't sell your data" posture the rest of `/get-help` already states.

## Placement (Phase A)

Embed the chooser directly at the top of `/get-help`, above the existing static list — don't fragment it onto a separate route. Someone who wants to skip the questions should be able to just scroll past it to the list that's already there today.

## What must not change

No new database table for the fixed tree, the AI-assisted routing, or Phase B's rate limiting itself — a lightweight counter/cache is fine for rate limiting, this doesn't need a durable table of conversations. Don't collect or store which answers a visitor picks (or asks, in Phase B) tied to any identity or case data beyond what Phase B's rate limiting genuinely requires — this page already tells visitors "we don't sell your data or run ads either" (see the existing copy in `get-help/page.tsx`); keep that true. Don't imply any recommendation — fixed-tree, AI-assisted, or Phase B's anonymous answers — is a legal determination; it's a free, informational pointer to the right free resource, same "not a referral service, not an endorsement" framing the rest of the page already uses. Both AI paths must reuse the existing guardrail-tested chat/guardrail infrastructure rather than a fresh, unvetted prompt — and must never recommend AI chat in place of a licensed human for court/representation-need situations, per the hard guardrail above, in Phase A and Phase B alike.
