# New task for Claude Code — round 88: standing order — always provide step-by-step guides with links for anything left for Peter

**Status: authorized now, Sep 14. This is a standing process instruction, not a feature to build — add it to CLOUD_CLAUDE.md as a permanent rule, not a one-time task to complete and move past.**

## The rule

**Whenever Claude Code reports that something needs Peter's own action** (an account signup, a console click, a login, anything that isn't Claude Code's to do) — the report must include a real step-by-step guide with the actual, full URL built in for each step, not just a bare item like "Reddit API app (link above) → give me the client ID/secret."

## Why this is now a standing order, not a one-off ask

Round 86's report listed three items "left for Peter" as short bullet points. Two of the three genuinely needed more than that: Peter had to ask for the actual step-by-step process before he could act, which is exactly the friction this rule exists to remove. This should be the default going forward, every time, not something requested after the fact.

## What "good" looks like — the round 87 task doc as the reference example

See round 87's Item 1 and Item 3 sections for the standard to match going forward: numbered steps, the real URL spelled out in full (e.g. https://www.reddit.com/prefs/apps, https://cron-job.org) rather than "the link above" or a bare domain name, and specific enough that Peter never has to ask a follow-up question just to know what to click. Every future round's "left for Peter" section — whether in the task doc itself, in a status update, or in CLOUD_CLAUDE.md — should meet this same bar.

## Also applies retroactively when reporting status

If a future status report (like round 86's) needs to tell Peter something is outstanding on his end, that report itself needs to follow this same standard — not just future task docs. The bar is "could Peter act on this immediately without asking what to click," every time.
